📋 Test Scenarios & Exercises

Practice real-world testing scenarios from beginner to advanced level

🔥 Smoke Testing

Smoke tests verify that the most critical functions work. Run these before detailed testing.

BEGINNER Basic Application Smoke Test

Verify the application loads and core features are accessible.

  1. Open the application URL (https://qa-training-labs.onrender.com)
  2. Verify the home page loads without errors
  3. Click on "Products" - verify products page loads
  4. Click on "Login" - verify login page loads
  5. Click on "API Docs" - verify Swagger UI opens
  6. Check browser console for JavaScript errors
Expected: All pages load within 5 seconds, no console errors, all navigation links work.

BEGINNER Authentication Smoke Test

Verify users can register and login successfully.

  1. Navigate to Register page
  2. Create a new account with valid details
  3. Verify registration success message
  4. Logout (if auto-logged in)
  5. Login with the new credentials
  6. Verify dashboard loads with user name
Expected: User can register, login, and access dashboard. JWT token is stored.

BEGINNER E-Commerce Flow Smoke Test

Verify the core shopping flow works end-to-end.

  1. Login as a user
  2. Browse products page
  3. Add a product to cart
  4. View cart - verify item appears
  5. Proceed to checkout
  6. Complete order with shipping address
  7. Verify order appears in Orders page
Expected: Complete purchase flow works. Order status shows "pending".

MEDIUM API Smoke Test with Postman

Verify all critical API endpoints respond correctly.

  1. GET /api/health - Should return 200
  2. POST /api/seed - Should seed database
  3. POST /api/auth/login - Should return token
  4. GET /api/products - Should return product list
  5. POST /api/cart/add (with auth) - Should add item
  6. POST /api/orders (with auth) - Should create order
Expected: All endpoints return expected status codes (200/201). Response times under 2 seconds.

🔄 Regression Testing

Regression tests ensure existing functionality still works after changes. These are comprehensive test suites.

MEDIUM User Management Regression Suite

Complete test suite for user-related functionality.

Registration Tests:

  1. Register with valid data → Success
  2. Register with existing email → Should fail
  3. Register with invalid email format → Should fail
  4. Register with short password (<6 chars) → Should fail
  5. Register with empty fields → Should fail
  6. Register with very long name (1000+ chars) → Check behavior

Login Tests:

  1. Login with valid credentials → Success + token
  2. Login with wrong password → 401 error
  3. Login with non-existent email → Error
  4. Login with empty fields → 400 error
  5. Verify token works for protected routes
  6. Verify token expiration behavior
Expected: All positive cases pass. Negative cases return appropriate errors. Document any bugs found!

MEDIUM Product Catalog Regression Suite

Read Operations:

  1. List all products → Returns array
  2. Get single product by ID → Returns product
  3. Get product with invalid ID → Should handle gracefully
  4. Get non-existent product → 404 error
  5. Search products by name → Filtered results
  6. Filter by category → Correct filtering

Write Operations (Admin):

  1. Create product with valid data → 201 Created
  2. Create product with negative price → Check validation
  3. Create product with zero stock → Should work
  4. Update product price → Verify change
  5. Delete product → Verify removal
  6. Non-admin create product → Should be denied (403)

MEDIUM Shopping Cart Regression Suite

  1. Add item to empty cart → Item added
  2. Add same item twice → Check if quantity increases or duplicates
  3. Add item with quantity 0 → Check validation
  4. Add item with negative quantity → Check validation
  5. Add out-of-stock item → Check behavior
  6. View cart → Shows all items with totals
  7. Remove item from cart → Item removed
  8. Clear entire cart → Cart empty
  9. Cart persists after logout/login → Check persistence
  10. Add more quantity than stock → Check validation

ADVANCED Order Management Regression Suite

  1. Create order with items in cart → Order created
  2. Create order with empty cart → Check behavior
  3. Verify order total calculation → Math correct?
  4. Verify stock decreases after order → Check inventory
  5. View order history → All orders shown
  6. View single order details → Correct data
  7. Cancel pending order → Status changes
  8. Cancel already shipped order → Should fail
  9. View another user's order → Check authorization
  10. Cancel another user's order → Check authorization
  11. Verify stock restores on cancellation → Check inventory

✅ Functional Testing

Test each feature against its requirements. Focus on what the system should do.

BEGINNER Form Validation Testing

Test all input forms for proper validation.

Registration Form:

  1. Submit empty form → Error messages for all fields
  2. Enter invalid email (no @) → Email validation error
  3. Enter mismatched passwords → Password match error
  4. Enter name with special characters → Check acceptance
  5. Enter extremely long values → Check max length

Checkout Form:

  1. Submit with empty address → Validation error
  2. Enter invalid ZIP code format → Check validation
  3. Enter numbers in city field → Check acceptance

BEGINNER Navigation Testing

  1. All navbar links work correctly
  2. Logo links to home page
  3. Login/Logout buttons show based on auth state
  4. Protected pages redirect to login when not authenticated
  5. Back button works correctly
  6. Refresh maintains current state
  7. Direct URL access works for all pages

MEDIUM Search & Filter Testing

  1. Search with exact product name → Find product
  2. Search with partial name → Find matching products
  3. Search with no results → Show "no products" message
  4. Filter by category → Only that category shown
  5. Combine search + filter → Both applied
  6. Clear filters → All products shown
  7. Search with special characters → No errors
  8. Search with SQL/NoSQL injection → No errors/exposure

MEDIUM Boundary Value Testing

  1. Quantity: 0 (boundary) → Check behavior
  2. Quantity: 1 (minimum valid) → Should work
  3. Quantity: -1 (below minimum) → Should fail
  4. Quantity: 999999 (very large) → Check limit
  5. Price: 0.00 → Check if allowed
  6. Price: 0.01 (minimum) → Should work
  7. Price: -0.01 → Should fail
  8. Password: 5 chars (below min) → Should fail
  9. Password: 6 chars (at min) → Should work
  10. Password: 100 chars (long) → Should work

🔌 API Testing

Test REST API endpoints using Postman or Swagger UI. Verify request/response handling.

BEGINNER HTTP Methods Testing

  1. GET /api/products → 200 OK + product array
  2. POST /api/auth/login → 200 OK + tokens
  3. PUT /api/products/:id → 200 OK + updated product
  4. DELETE /api/products/:id → 200 OK + confirmation
  5. PATCH /api/orders/:id → 200 OK + updated order
  6. Wrong method (DELETE on /login) → Should return 404 or 405

MEDIUM Status Code Verification

  1. Successful GET → 200 OK
  2. Successful POST (create) → 201 Created
  3. Missing required field → 400 Bad Request
  4. Invalid credentials → 401 Unauthorized
  5. Access denied (non-admin) → 403 Forbidden
  6. Resource not found → 404 Not Found
  7. Server error → 500 Internal Server Error
  8. Document any inconsistent status codes (BUGS!)

MEDIUM Request/Response Validation

  1. Verify Content-Type header is application/json
  2. Verify response structure matches documentation
  3. Verify all required fields are present
  4. Verify data types are correct (string, number, boolean)
  5. Test with missing Content-Type header
  6. Test with wrong Content-Type (text/plain)
  7. Test with malformed JSON body
  8. Test with extra unexpected fields

ADVANCED API Automation with Postman

  1. Import the Postman collection
  2. Set up environment variables (baseUrl, token)
  3. Write pre-request script to auto-login
  4. Write test scripts to validate responses
  5. Create test for each endpoint
  6. Run collection with Newman (CLI)
  7. Generate HTML test report
  8. Set up collection to run in CI/CD
Example Postman Test: 
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Response has products array", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.be.an('array');
    pm.expect(jsonData.length).to.be.above(0);
});

🔒 Security Testing

Test for common security vulnerabilities. This lab has intentional security bugs to find!

MEDIUM Authentication Security

  1. Try accessing protected endpoints without token → Should get 401
  2. Try using expired token → Should get 401
  3. Try using malformed token → Should get 401
  4. Try brute force login (many attempts) → Check rate limiting
  5. Check if password is hashed in database responses
  6. Verify token changes after password change
  7. Check token invalidation after logout

MEDIUM Authorization Testing (IDOR)

Insecure Direct Object Reference - can users access other users' data?

  1. Login as User A, get an order ID
  2. Login as User B
  3. Try to GET User A's order using the ID → Should be denied
  4. Try to DELETE User A's order → Should be denied
  5. Try to modify User A's cart → Should be denied
  6. Try to access /api/users (admin only) as regular user
  7. Document any IDOR vulnerabilities found!

ADVANCED Injection Testing

  1. Try SQL injection in login: ' OR '1'='1
  2. Try NoSQL injection: {"$gt": ""} in email field
  3. Try XSS in product name: <script>alert(1)</script>
  4. Try command injection in fields
  5. Check if inputs are sanitized
  6. Check if outputs are encoded
  7. Test for path traversal: ../../../etc/passwd

ADVANCED Mass Assignment Testing

  1. During registration, try adding "role": "admin" to the request body
  2. Check if you become an admin
  3. Try adding "isActive": true when updating profile
  4. Try adding unexpected fields to any POST/PUT request
  5. Check which fields are protected vs exposed
Security Bug Found? If you can set role:admin during registration, that's a critical vulnerability!

⚡ Performance Testing

Test application speed, responsiveness, and stability under load.

BEGINNER Response Time Testing

  1. Use browser DevTools Network tab
  2. Measure page load time for Home page → Should be <3s
  3. Measure API response time for GET /api/products → Should be <500ms
  4. Measure login response time → Should be <1s
  5. Measure order creation time → Should be <2s
  6. Test on slow 3G network (DevTools throttling)

MEDIUM Load Testing Basics

  1. Open 5 browser tabs with the application
  2. Perform actions simultaneously
  3. Check if all requests complete successfully
  4. Check for any timeout errors
  5. Monitor response times during concurrent use
Note: Free tier hosting may have limits. Document any performance degradation.

ADVANCED API Load Testing with Tools

  1. Install a load testing tool (k6, Artillery, or Apache JMeter)
  2. Create a test script for GET /api/products
  3. Run with 10 virtual users for 30 seconds
  4. Analyze response times (avg, p95, p99)
  5. Identify the breaking point
  6. Generate a performance report
Example k6 script: 
import http from 'k6/http';
import { check, sleep } from 'k6';

export let options = {
  vus: 10,
  duration: '30s',
};

export default function () {
  let res = http.get('https://qa-training-labs.onrender.com/api/products');
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}
