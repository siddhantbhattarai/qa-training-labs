🎓 QA Curriculum — Beginner to Advanced

Follow the modules in order. Each one tells you which difficulty level to set, what to test, and what to record.

How the difficulty switch works

Use the Level dropdown in the top bar (just like DVWA's security selector). The same feature gets buggier or cleaner as you change it:

  • LOW obvious functional defects — learn smoke & functional testing.
  • MEDIUM boundary & negative cases — learn BVA & equivalence partitioning.
  • HIGH subtle business-logic & integration defects — learn exploratory & regression testing.
  • STABLE the correct reference build — learn expected behaviour & use it as a regression baseline.

Tip: testers using Postman/curl can set X-QA-Level: low per request instead. New to the tooling? See Tools You'll Use.

1

Foundations & Smoke Testing

LOW

Get the app running, learn the domain, and confirm the critical path works at all.

  • Run the app (npm start), open the home page, register and log in.
  • Browse products, add to cart, place an order — end to end once.
  • Do the Smoke Test checklist.
  • Deliverable: a 10-line smoke test summary (what worked / what didn't).
2

Functional Testing & Bug Hunting

LOW

Find the obvious functional defects and write your first bug reports.

  • Test each form and flow against what you'd expect.
  • Open the Bug Hunt and find as many Low defects as you can.
  • Read the Reporting Guide and file 5 proper bug reports.
  • Deliverable: 5 bug reports using the template.
3

Boundary & Negative Testing

MEDIUM

Switch to Medium. The obvious bugs are fixed — now hunt the edges.

  • Apply Boundary Value Analysis: password length 7/8/9, quantity 0/1/stock/stock+1, discount 100/101.
  • Apply Equivalence Partitioning to the email field (valid / invalid classes).
  • Re-test the Low bugs: which are fixed? (That's regression thinking.)
  • Deliverable: 8+ test cases (template) incl. negative cases, with results.
4

API Testing

MEDIUM

Test the API directly — status codes, schemas, and contracts.

  • Explore Swagger; import the Postman collection in /postman.
  • Set the difficulty with the X-QA-Level header and observe how responses change.
  • Check status codes (400 vs 500 vs 404), and compare response bodies to the documented schema.
  • Deliverable: an API test run with at least 5 status-code/contract defects.
5

Business-Logic & Exploratory Testing

HIGH

Switch to High. The remaining defects only show up when you combine steps and track state.

  • Test multi-step flows: add to cart → change price → checkout (stale price?).
  • Track stock through place-order → cancel cycles (is it restored?).
  • Test the order status lifecycle for illegal transitions.
  • Deliverable: 2 exploratory session notes describing state-based defects.
6

Regression Testing with the Stable Baseline

STABLE vs HIGH

Use Stable as your "expected behaviour" oracle.

  • Run a test on a buggy level, then the same test on Stable, and diff the results.
  • Build a small regression suite: one row per test, expected (Stable) vs actual (level).
  • Deliverable: a regression test sheet (test-case template) covering cart & orders.
7

Reporting & Test Summary

ALL LEVELS

Turn your findings into professional artifacts.

  • Polish your bug reports (severity vs priority, evidence, repro steps).
  • Write a Test Summary Report for the cart/order area across levels.
  • Read the full Reporting Guide and grab the templates.
  • Deliverable: a portfolio-ready bug report set + one test summary.
8

Automation & CI

LOW → STABLE

Stop testing by hand — encode your tests as code and let CI run them on every change. This module ships as a real, runnable suite in the repo.

  • Set up Playwright — one framework for both API and E2E browser tests: npm install && npx playwright install chromium, then npm test.
  • Read tests/README.md and study tests/api/defect-detection.spec.js — it asserts the correct (Stable) behaviour and runs it at every level, marking buggy levels test.fail(). That's a regression suite in miniature.
  • Run the same suite against the live demo, not just localhost: BASE_URL=https://qa-training-labs.onrender.com npm run test:smoke.
  • Run the Postman collection headless with Newman: npm run test:postman.
  • See it in CI: .github/workflows/ci.yml runs the whole suite on every push and uploads the report.
  • Deliverable: add one new API test and one new E2E test (see the exercises in tests/README.md) and get them passing in CI.

Ready? Set the level to LOW in the top bar and start Module 1.
