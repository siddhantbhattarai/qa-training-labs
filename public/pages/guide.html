📋 Manual Testing Guide

What is Manual Testing?

Manual testing involves manually executing test cases without using automation tools. It's the foundation of QA and helps you understand user experience firsthand.

Key Testing Techniques

1. Boundary Value Analysis

Test at the edges of input ranges. For example, if quantity should be 1-100: test 0, 1, 50, 100, 101, -1, and very large numbers.

2. Equivalence Partitioning

Divide inputs into groups that should behave the same. Test one value from each group. Valid emails, invalid emails, empty input, special characters.

3. Exploratory Testing

Freely explore the application without predefined test cases. Follow your intuition, try unusual workflows, and think like a user who might make mistakes.

4. Negative Testing

Try to break the application with invalid inputs: empty fields, SQL injection, special characters, extremely long strings, and unexpected data types.

Practice Exercise

Test the registration form with these scenarios:

  • Empty email, empty password, empty name
  • Invalid email formats (no @, no domain, spaces)
  • Password variations (too short, no numbers, no uppercase)
  • Already registered email
  • Special characters in name field
  • Very long inputs (1000+ characters)

API Testing Checklist

Example: Testing Login Endpoint

# Valid login
POST /api/auth/login
{
    "email": "john@example.com",
    "password": "Password123"
}
# Expected: 200 with accessToken

# Invalid password
POST /api/auth/login
{
    "email": "john@example.com",
    "password": "wrongpassword"
}
# Expected: 401 Unauthorized

# Missing fields
POST /api/auth/login
{}
# Expected: 400 Bad Request

🤖 Automation Testing Guide

Python Example with pytest

import requests
import pytest

BASE_URL = "https://your-app.onrender.com/api"

class TestAuth:
    def test_register_success(self):
        response = requests.post(f"{BASE_URL}/auth/register", json={
            "name": "Test User",
            "email": "test@example.com",
            "password": "Password123"
        })
        assert response.status_code == 201
        assert "accessToken" in response.json()

    def test_login_invalid_credentials(self):
        response = requests.post(f"{BASE_URL}/auth/login", json={
            "email": "wrong@example.com",
            "password": "wrongpass"
        })
        assert response.status_code == 401

    def test_login_missing_password(self):
        response = requests.post(f"{BASE_URL}/auth/login", json={
            "email": "test@example.com"
        })
        # BUG: Should be 400, might return 500
        assert response.status_code == 400

JavaScript Example with Jest

const axios = require('axios');

const BASE_URL = 'https://your-app.onrender.com/api';

describe('Products API', () => {
    let token;

    beforeAll(async () => {
        const res = await axios.post(`${BASE_URL}/auth/login`, {
            email: 'admin@qalab.com',
            password: 'Admin@1234'
        });
        token = res.data.accessToken;
    });

    test('should list all products', async () => {
        const res = await axios.get(`${BASE_URL}/products`);
        expect(res.status).toBe(200);
        expect(Array.isArray(res.data.products)).toBe(true);
    });

    test('should not allow negative price', async () => {
        // BUG: This might actually create the product!
        try {
            await axios.post(`${BASE_URL}/products`, {
                name: 'Test Product',
                price: -10,
                stock: 100
            }, {
                headers: { Authorization: `Bearer ${token}` }
            });
            fail('Should have rejected negative price');
        } catch (error) {
            expect(error.response.status).toBe(400);
        }
    });
});

🐛 Bug Reporting Guide

Good Bug Report Template

Title: [Severity] Brief description of the bug

Environment:

  • URL: https://your-app.onrender.com
  • Browser/Tool: Postman v10.0
  • User Role: Regular user

Steps to Reproduce:

  1. Login as user john@example.com
  2. Send POST to /api/cart with {"productId": "...", "quantity": -5}
  3. Observe the response

Expected Result:

400 Bad Request with error "Quantity must be positive"

Actual Result:

200 OK - Item added with negative quantity, cart total becomes negative

Severity: High

Users could potentially get money/credit by exploiting negative quantities

Severity Levels

Critical System crash, data loss, security breach, complete feature failure
High Major feature broken, no workaround, affects many users
Medium Feature partially broken, workaround exists, moderate impact
Low Minor issue, cosmetic problem, edge case, minimal impact
