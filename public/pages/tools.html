🧰 Tools You'll Use

The toolkit for testing this lab. Every name is a clickable link, with notes on how to use it for this project.

💡 Almost everything works against https://qa-training-labs.onrender.com. Set the difficulty with the Level dropdown (top bar) or the X-QA-Level header.

🌐 Web Browser + DevTools

Manual & UI testing · free

Your main tool for manual and frontend testing. Press F12 to open DevTools.

How to use it here:

• Network tab — click around the app and watch the real API requests/responses (status codes, bodies). Confirm the X-QA-Level response header to see which level you're testing.
• Console tab — read errors; the lab's QALevel.get() tells you the active level.
• Application → Cookies — see the qa_level cookie the switcher sets.

Try: open Network, add an item to the cart, and inspect the POST /api/cart/add call.

🎚️ Difficulty Switcher (built in)

Core to this lab

The DVWA-style level control in the top bar. The same feature gets buggier or cleaner as you change it.

How to use it here:

• In the browser: pick Low → Medium → High → Stable from the dropdown and re-run the same test.
• For API tools: send a header instead of clicking.

curl -s https://qa-training-labs.onrender.com/api/products/bad-id -H "X-QA-Level: low"     # 500 (defect)
curl -s https://qa-training-labs.onrender.com/api/products/bad-id -H "X-QA-Level: stable"  # 400 (correct)

Tip: write your bug report's Expected Result by running the same steps at stable.

📘 Swagger UI

API exploration · built in

Interactive API docs at /api/docs — no install needed.

How to use it here:

• Browse every endpoint and read the "Defects to find" notes.
• Click Try it out → Execute to call an endpoint live.
• Use Authorize (top right) to paste a JWT from login so protected routes work.

Start with POST /api/auth/login (admin@qalab.com / Admin@1234), copy the accessToken, then Authorize.

📮 Postman

API testing

The most popular API testing client. A ready collection ships with this repo.

How to use it here:

• Import postman/QA-Training-Lab.postman_collection.json and the environment in the same folder.
• Set the environment baseUrl to https://qa-training-labs.onrender.com.
• Add a header X-QA-Level: low (Collection → … → Edit → Headers) to test a whole run at one level, then change it and re-run for regression.

🏃 Newman

Run Postman from CLI

Runs a Postman collection from the command line — your first taste of automation/CI.

npm install -g newman
newman run postman/QA-Training-Lab.postman_collection.json \
  -e postman/QA-Lab-Local.postman_environment.json \
  --env-var "qaLevel=medium"

How to use it here:

Run the collection at each level and compare which requests change — instant regression evidence.

⌨️ curl

Quick API checks · pre-installed

Already on macOS/Linux. Perfect for fast, repeatable one-liners in a bug report.

# Log in and grab a token
TOKEN=$(curl -s https://qa-training-labs.onrender.com/api/auth/login -H "Content-Type: application/json" \
  -d '{"email":"user@qalab.com","password":"User@1234"}' | grep -o '"accessToken":"[^"]*"' | cut -d'"' -f4)

# Reproduce the "quantity 0 accepted" defect at Low
curl -i https://qa-training-labs.onrender.com/api/cart/add -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -H "X-QA-Level: low" \
  -d '{"productId":"PASTE_ID","quantity":0}'

How to use it here:

Paste the exact command + response into your bug report's Steps/Evidence.

🔎 jq

Read JSON responses

Pretty-prints and filters JSON so big responses are readable.

curl -s https://qa-training-labs.onrender.com/api/products | jq '.[].name'           # list product names
curl -s https://qa-training-labs.onrender.com/api/products -H "X-QA-Level: low" | jq 'length'

How to use it here:

Quickly check things like "does the list still include the inactive 'Webcam HD' product?" at each level.
